# Demo dataset — northwind_outfitters_sales.csv

Synthetic weekly sales data for a fictional outdoor-apparel brand. 936 rows,
18 months (2025-02-03 → 2026-07-27), 3 regions × 4 categories, generated by
`generate_demo_data.py` (not checked in — regenerate with the same `random.seed(42)`
logic if you need to tweak it).

Built for live product demos: it has a realistic trend, holiday seasonality
(Nov/Dec), and one deliberate, statistically-guaranteed anomaly for the
anomaly-detection feature to catch —

- **Row:** `week_start_date=2025-11-17`, `region=North America`, `category=Apparel`
- **Story:** a checkout outage the week before the holiday peak. Revenue and
  units collapse; `marketing_spend` does not (it was already committed), so
  the divergence itself is part of the signal.
- **Verified:** z-score ≈ 4.6 on the pooled `revenue` column — the single
  highest in the dataset, so the app's z-score ≥ 3 outlier check
  (`backend/app/analytics/anomaly_detection.py`) surfaces this exact row as
  the top anomaly, not a false positive elsewhere.

Upload this file as-is for a demo. Don't rename columns — `revenue`,
`units_sold`, `new_customers`, `marketing_spend`, and `avg_order_value` are
named to match the KPI detector's keyword list
(`backend/app/analytics/kpi_detector.py`) so they're picked up automatically.
